Q1: What am I actually doing in this Lesson 1 lab?

Q3: Is FastAPI the Slack integration?

AI's answer, in my own words:
No. FastAPI is the modern API layer of the Balerica application. It provides endpoints that other programs or clients can use to communicate with the application. In this lab it sits in front of the COBOL banking core, allowing modern HTTP/API requests to interact with older business logic.

How I checked it:
I checked the Student Runbook architecture and API endpoints table. The runbook lists FastAPI endpoints including GET /status, GET /accounts/{id}, POST /payments, GET /transactions, and POST /ask. I also started the FastAPI application myself with Uvicorn and confirmed that the application reached "Application startup complete."


Q4: What am I actually doing when I run source venv/bin/activate?

AI's answer, in my own words:
Activating the venv does not create another VM, container, or separate server. It changes the current shell environment so that the Balerica application uses the Python environment and dependencies installed specifically for the project. The EC2 instance and Linux session remain the same.

How I checked it:
I compared the explanation with Step 4 of the runbook, which tells me to activate the environment before starting Uvicorn. I also observed that my prompt changed to show (venv) after running source venv/bin/activate. When I opened a new SSH connection later, (venv) was no longer present in that new shell, confirming that the activation applied to the shell session rather than creating another machine.

AI's answer, in my own words:
The build can be automated, but the required seven manual runs are intended to teach me the process before I automate it. Once I understand each component and dependency, automation can reproduce those steps. The homework demonstrates this progression through the optional User Data and golden AMI exercises.

How I checked it:
